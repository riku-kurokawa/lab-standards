# ADR（設計判断の記録）を書く

## いつ書くか

- 複数の選択肢を比較して 1 つを選んだとき（手法、損失関数、前処理、評価指標、データ形式）
- 後から変えると影響が大きいとき（データのスキーマ、run の構成、座標系・単位系）
- 先行研究と異なる設定を採ったとき

## 手順

1. `uv run labkit adr "日本語のタイトル" --slug english-kebab-slug` で雛形を作る（番号は自動）。
2. 状態は最初「提案」。決定を実装して検証が通ったら「採用」に変える。人間に知らせたい判断は `labkit queue ask` に 1 行。
3. 見出しに沿って書く:
   - **背景**: 何が問題で、どんな制約があるか
   - **決定**: 何を選んだか（1〜3 文で明確に）
   - **理由と検討した代替案**: 各案の長所・短所、根拠となる run や文献（`runs/<id>`、`[@citekey]`）
   - **影響**: この決定で変わること、守るべきこと、見直す条件
4. 古い決定を覆すときは、古い ADR の状態を「置換（NNNN）」にし、新しい ADR を作る。古いものは消さない。
5. 開発ログの「判断と理由」から ADR へのパスを書く。
