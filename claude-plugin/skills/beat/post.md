# 人間への投稿（labkit post）

人間は devlog も台帳も読まない。読むのはフィード（`labkit view`）の投稿だけで、通勤中にスマホで流し読みするつもりで開く。
投稿は報告書ではない。「これは知らせないと人間が困る／喜ぶ」と自分で判断したことを、同僚に話しかけるように 1 件ずつ書く。

## 投稿するか（しないのが既定）

拍の終わりに 1 回だけ自問する: **この拍で、人間の理解か判断が変わることが起きたか。**

投稿する:
- 主線の問いへの答えが動いた（効いた・効かなかった・予想が大きく外れた）
- 前に伝えたことが誤りだった（撤回。良い知らせより先に、同じ大きさで）
- 人間にしか決められないことがあり、どちらを選ぶかで今後の数時間が変わる（相談）
- 主線の項目が閉じた、主線を替えた（節目）

投稿しない: 予定どおり進んだ、計算を投げた、台帳を整えた、小さな修正、次にやること。これらは拍の 3 行で足りる。
1 日 5 本まで（`[post] per_day`）。上限に当たったら設定を変えず、どれが重要かを選び直す。3 日何も無ければ、それも 1 行の節目として書く。

## 書き方

書く前に 3 つ決める: 何が重要か。人間は読んだあと何をすればよいか。どの図が 1 枚あれば言葉が要らなくなるか。

```
uv run labkit post "<結論の 1 行>" --body @scratch/post.md \
    --fig "<png>::<この図で見るところ>" [--code src/pkg/x.py:40-62] [--detail @scratch/more.md] \
    [--kind finding|retract|ask|milestone] [--option "A 案" --option "B 案"]
```

- **見出しは結論**（60 字）。「〜を調べた」ではなく「〜だった」。数字が 1 つ入ると強い。
- **本文は 500 字**。最初の文で何が分かったか、次になぜ重要か、最後に次の一手。経過・手順・ファイル名は書かない。
  人間が知らない略語・run 名・項目番号を主語にしない。強調（`**…**`）は 1 か所。
- **数値は引用で書く**: `uv run labkit cite <run> <key>` の出力（`5.05 m/s [run:…:key]`）をそのまま貼る。
  投稿の時点で metrics.json と照合され、画面では ✓ になる。合わない数値は投稿できない。
- **図は、この投稿のために作る**（`labkit fig`。skill: make-figure）。run の図をそのまま貼らない。1 枚で主張が読めること:
  比べる相手（基準・公表値・予想）を同じ図に入れ、系列は 2〜3 本、凡例ではなく線の横に名前を書き、見てほしい差に注記を付ける。
  `::` の後の「見るところ」は、図のどこを見れば見出しが正しいと分かるかを 1 文で。
- **コードは、判断に効く 5〜20 行だけ**（誤りの原因だった行、新しい式の本体）。変更の一覧は貼らない。
- **補足（--detail）** は折りたたまれる。なぜ見逃したか、まだやっていないこと、盲検でない等の注意はここへ。
- **相談（ask）** は選択肢を 2〜3 個に絞り、本文に「いまはどちらで進めているか」「変えると何が取り直しになるか」を書く。返事は待たない。

## 返信

人間の返信は次の `labkit beat start` の先頭に出る。その拍で最初に対応し、
`uv run labkit note done N00x --reply "<何を変えたか。変えないなら理由>"` で答える（同じ投稿のスレッドに出る）。「了解」には答えなくてよい。
