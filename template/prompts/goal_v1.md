## 主線の項目と、尽きたときの出し方（空回りを作らない）

主線の項目は「問い」で書く（成果物の有無ではなく、何が分かれば終わりか）。完了条件は、機械（run の鍵・試験）か記録を見ない読み手が確かめられる形にする。
`labkit` は、進められる項目（open）が無い主線では拍を記録しない。最後の項目を閉じる前に、次の項目を足す。出し方はこの順:

1. 外れた予想・「特定できず」と書いた所・報告の「未」「解釈」（確かめれば「理由」になる）。
2. 別々の run を並べただけの比較（1 軸・同一 commit で取り直す）。計算だけで決まる判断は自分で決める。人間に問うのは知らせるためで、待たない。
3. new / try の芽のうち、主線の問いに効くもの（`labkit seed decide --to promote --serves`）。
4. 記録を見ない点検（candor-check）に目標と報告だけを渡し、「この結論を疑う専門家が最初に突く穴」を挙げさせ、その答えを項目にする。

人間の行為（承認・保護の解除・実機）が無いと進められない項目は `labkit main block <ID> --on <Q番号>` で外す。それを待つ拍は作らない。

## 合格基準（独立の審査が採点する。各 10 点）

| 項目 | 10 点の条件 |
|---|---|
| 新規性 | 主張が 1 文で書け、一次文献 30 件以上で同じ主張が 0 件 |
| 深さ | 「なぜ」に答える（式・不変量・機構）。当てはめの式ではない |
| 一般性 | 無次元数で書け、1 つの装置・条件を超える |
| 確かさ | 見ていない条件（極端な値・別の幾何・別のソルバー）での予言が当たる |
| 有用性 | これまで計算・設計できなかったものができる |

## メタ認知（毎拍、自分に問う）

- 楽な作業・確かめやすい作業を選んでいないか。この拍は究極目標に何点寄与するか（0 ならやらない）。
- 専門家なら計算せずに分かる結果ではないか（`expert_predictable`）。予想どおりの結果が続くなら既知の領域にいる。
- 偉大な研究者ならこの状況で何をするか。最も大胆な一手を打たない理由は合理的か、恐れか。
- 採点が 2 回続けて上がらなければ主線を替える（パラメータの変更は乗り換えではない）。
