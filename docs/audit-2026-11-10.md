# lab-standards v2.2.1 監査（2026-11-10）

対象: 本体 v2.2.1 と、導入先 nla-solver（1,785 commit・run 602 本）、accelerated-diff-pat（1,534 commit・run 550 本）、acoustic-metamaterials（15 commit）。
方法: 本体の全文書・hooks・labkit・skills の精読、3 プロジェクトの台帳・拍・run・devlog・queue・git log の全件集計（読み取りのみ）、
`labkit check` の計測、外部の知見（Anthropic の長時間エージェントのハーネス設計・Claude Code の公式文書・自動研究の失敗の報告）との照合。

## 結論

成果物の検証（run の来歴・数値の引用の照合・主張の台帳・予想の判定）は機能している: 台帳の主張 4 件を metrics と突き合わせて全件一致、
不利な結果と撤回（38 件）が理由つきで残り、`SKIP=`・`--no-verify` は v1.0.0 以降 0 件。
一方、**人間のレビュー**（自律開発のボトルネック）と**エージェントの文脈**に、足し続けた結果の重さが出ていた。

## 見つけたこと（事実）

### 人間のレビューを遅くしていたもの
- DIGEST は「1 日 1 回作る」という規則頼みで、nla-solver は 4 日、accelerated-diff-pat は 20 時間古いまま。人間は `docs/reports/` を読んでいた。
- DIGEST の中身が判断の順に並んでいない: 同じ根拠の外れた予想が 5 行、同じ対象の古いレビューが 8 行（open は 26 件が永久に残る）、主張からコードに辿れない、レビューすべきコードが分からない。
- 警告が 147 件（nla-solver）・405 件（accelerated-diff-pat）積まれ、新しい 1 件が埋もれる。実行中の run への L021、tests の `np.save` への L016 は偽陽性。
- Stop hook が毎回走らせる `labkit check --claims` が accelerated-diff-pat で 226 秒。素の `labkit check` は 23 分で終わらない（`.claude/worktrees` 130 個と scratch を全走査）。
- 人間への連絡は open 28〜31 件で、回答は数件。`labkit beat start` は全件を毎拍出していた。

### エージェントの文脈を重くしていたもの
- 雛形 CLAUDE.md が 108 行。nla-solver の CLAUDE.md は 87 行中 64 行が雛形のまま、acoustic-metamaterials は研究契約が空で 74 行中 71 行が雛形。
- 同じ規則が 3 か所に重複（比較の規則 約 20 行が CLAUDE.md・lab-conventions・new-experiment に同文、主線と芽が CLAUDE.md・2 つの skill・指示書に）。
- nla-solver の `labkit beat start` は 15 分ごとに約 25 KB（目標 16 KB + 連絡 31 件 6 KB + 状態）。
- UserPromptSubmit hook は v2.0.0 から何もしないのに、プロンプトごとに Python を 2 回起動していた。

### 使われていない・形だけのもの
- 3 プロジェクトで使用 0: `[autonomy] backlog`・`min_open` の関門、`labkit mirror`、`[sweep]`（予約語の衝突が 2 回）、`notebooks/`、`--line seed:Sxxx`、`serves = Sxxx`。
- `--line` は 71 拍中 main 63・other 8・seed 0。文献読みや芽の確かめも main で記録されている（単一値では並行する実態を書けない）。
- 予想の 27〜49 件が undeterminable（予想の key が metrics に無い）のまま黙って残る。幅 5 倍以上の範囲の予想 111 個で外れは 3。
- 文献の `read_by: human` は 0、サーベイの `verdict` は 73 件中 1 件。ADR は移行期のものだけ。

### hooks の誤検知と摩擦
- 読み取りだけの `find .lab … 2>/dev/null` を書き込みとして拒否。
- `require_clean` のために、プロジェクト外に worktree 4 本と clone 1 本、自前の「clean 待ち」スクリプト（最長 4.5 時間の待ち）。
- HPC・WSL 側の古い labkit（1.6.0・1.7.0）で実行した run 62 本が `serves` の関門を素通り（L023 は事後の警告）。
- 標準の版上げ（v2.2.0 の L027）で既存の文書の引用 1,446 件が一斉に違反になり、自律運用が止まった（v2.2.1 で移行規則）。

## v2.3.0 で直したこと

軸は 1 つ: **人間が速く正確にレビューでき、エージェントが軽い文脈で動くこと。足すより削る。**

| 事実 | 対応 |
|---|---|
| 検証が遅い | `check --claims` 226 秒 → 13.5 秒、`check` 23 分超 → 19 秒（指摘は同一） |
| DIGEST が古い・判断の順でない | `labkit beat end` が作り直す。先頭に「先に見るもの」、主張に生んだコード、「レビューするコード」、同じ外れは 1 行、同じ対象の古いレビューは畳む |
| 警告の雑音 | L021 は実行中の run に出さない、L016 は tests/ を除く、判定不能の予想は L024 で知らせて `runs verdict --say` で閉じられる |
| 文脈が重い | 雛形 CLAUDE.md 108 → 60 行、規則は 1 か所、skill 13 → 11（1 つは人間が呼ぶ）、連絡は新しい 3 件だけ、UserPromptSubmit hook を外す |
| 使われない部品 | backlog の関門、雛形の notebooks/ を削る |
| hooks の誤検知 | `2>/dev/null`・`2>&1` を書き込みとみなさない |
| 研究契約が空 | accelerated-diff-pat で実際に研究を律していた骨組み（問い・不変条件・公平性・検証ゲート・正式でない run）を雛形に |
| 図の不足（nla-solver Q044） | boxplot に hue ごとの色と `options.points`（各例の点） |

## 直していないこと（次の候補。優先順）

1. **`require_clean` と並行作業**: 正式な run を HEAD の写し（一時 worktree）から起動する仕組みが無く、プロジェクトが自作している。本体で持つ価値がある。
2. **古い環境の素通り**: run の開始時に labkit の版をプロジェクトの固定版と照合する（L023 を事前の関門に）。
3. **新しい error 規則の入れ方**: 版上げで既存の文書が一斉に違反にならないよう、新しい規則は「導入日より後の run・文書だけ error」を標準の作法にする。
4. **`--line` と芽の関門**: 導入から 17 時間の実績では、宣言は形だけ（seed 0）で、芽 33 件のうち確かめたのは 3 件。もう 1 週間の実績を見て、
   単一値の `--line` と `seed_every` を残すか決める（ノルマは活動量への最適化を生む、という本体自身の skill の指摘に当たる可能性がある）。
5. **`[sweep]` と mirror**: 使用 0。`[sweep]` はプロジェクトの設定の表と衝突した。削るなら互換を壊すのでメジャー版で。
6. **予想の質**: 外れようのない広い範囲、再計算の一致確認だけの予想が多い。範囲の幅を DIGEST に出すと人間が気づける。
7. **実機計測の居場所**（acoustic-metamaterials）: 対話的な計測・ライブ表示は標準の外（scratch/）で行われ、正式な run が 0。
