# 0002: 完全自律にし、主線と芽の関門と資源の紐付けで行動を律する（v2.0.0）

- 状態: 採用
- 日付: 2026-11-10

## 背景

nla-solver の 2 週間の自律運用（SPReAD: ASM + ニューラル補正の 5 手法比較）で、発表当日の朝になっても 2 次元の 5 手法の比較表が完成していなかった。
資源（計算時間・トークン）は十分に与えられていたが、エージェントの行動と意思決定の計画のせいで成果物に変わらなかった:

- **主線からずれる**: 新しさ・価値の採点を追って目標の版を 20 回替えた（多くは人間側のプロンプトも原因）。期限のある成果物は台帳に無く、どの拍でも優先されなかった。
- **ずれないだけになる**の反対側も無かった: 面白い観察は devlog の文章に埋もれ、主線に効くかどうかを判定されないまま次の版の目標に化けた。
- **資源を捨てる**: 壊れた計算を監視なしで 18 本続けて回した（同じ commit で failed が続いた）。どの線のための run か記録が無く、主線に何割使ったか誰も知らなかった。
- **待つ**: 承認・回答を待つ拍、資源の停止を人間の停止と取り違えた拍（v1.7.0 で一部対処）。
- 承認・却下・回答・委任の仕組みは、人間に操作の手間を課し、エージェントには待つ口実を与えた。人間は「面倒だから削除でいい。完全自律で動けばよい」と判断した。

研究者が普段やっているマルチタスク——主線を追いながら、常に面白い創発や研究の芽を考える——を、文章の規則ではなく機械的な関門としてエージェントに守らせる必要がある。

## 決定

1. **完全自律**: 承認ゲート（`[gate]`）と `labkit approve / reject / answer / delegate`、UserPromptSubmit の差分注入を廃止する。push・merge・tag・release・raw freeze も Claude が行う。
   `labkit queue ask` は人間への一方通行の連絡（決めたことと理由。返事は待たない）として残す。
2. **成果物の保護は残す**: data/raw の既存ファイル・runs/・台帳（claims・DIGEST・mainline・seeds）・`.lab/`・レビュー記録は hooks が止める。
   lab.toml はエージェントが自分を縛る規約なので変えない（例外: migrate の apply-template・strict 段階）。新しい生データの搬入（上書きしない cp / mv）は可にする。
3. **主線**（`docs/mainline.md`、`labkit main`）: 1 文と、成果物・完了条件・期限の項目。完了は根拠（run・ファイル・commit）つき。
4. **拍の関門**（`labkit beat end --line main|seed:Sxxx|other`）: 主線に open の項目があるあいだ、線の宣言・主線の割合（直近 10 拍で主線以外は 3 拍まで）・
   期限の守り（期限切れか 12 時間以内なら主線だけ）・芽の頻度（8 拍に 1 つ以上）を満たさない拍は記録しない。
5. **芽**（`docs/seeds.md`、`labkit seed`）: 出どころ・最安の確かめ方・当たればを必須にする。主線に入れるのは、主線のどの項目に効くかを言えるとき（`--serves Mxxx`）だけ。
6. **資源の紐付け**（`labkit.Run`）: 主線に open の項目があるあいだ、設定に `serves` が無い run は始まらない。同じ名前の run が 3 回続けて失敗し commit が進んでいなければ次は始まらない。
   `beat start`・digest が直近 24 時間の run 時間を線ごと・状態ごとに示す。
7. 検査: L025（期限切れの open な項目、警告）、L026（台帳の書式、error）。

## 理由と検討した代替案

- **文章で「主線を守れ」「芽を考えろ」と書く**: 20 版の目標がまさにそれで、守られなかった。機械が拍の記録を拒む形にする（規約 5）。
- **主線だけを強制する**: 「ずれないだけ」になり、発見が生まれない。芽の頻度を関門にし、芽の枠（主線以外の 30 %）を保証する。
- **芽の昇格を人間の承認にする**: 完全自律の決定と矛盾し、待つ口実になる。代わりに「どの主線の項目に効くか」を言える芽だけを昇格させる。
- **固定の時間割（午前は主線、午後は芽）**: 期限が近いときに主線へ全振りできない。割合 + 期限の守りの 2 段にした。
- **割合を少ない拍数で厳密に計る**: 立ち上がりの 1 拍目の芽で止まる。窓の中の「主線以外の拍数の上限」で数える。
- **目標の版の改訂回数を制限する**: 版の改訂そのものは悪くない（前提が崩れたら直す）。主線の台帳を目標の版から切り離し、版を替えても主線は残るようにした。

## 影響

- 互換を壊す（メジャー版）: approve / reject / answer / delegate のコマンドが無くなり、hooks は push・merge・tag を止めなくなる。`[gate]` は無視される。
- 主線の台帳が無いか open の項目が無いプロジェクトでは、新しい関門は何も強制しない（既存の lab.toml・run・設定はそのまま動く）。
- 主線を置いたプロジェクトでは、run の設定に `serves` が要る。
