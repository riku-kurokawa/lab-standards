# lab-standards v0.4.0 監査（2026-11-02）

対象: riku-kurokawa/lab-standards（108 commit、うち 105 が 2026-11-01）、導入先 accelerated-diff-pat（v0.4.0）と nla-solver（v0.3.1）。
方法: 本体の全文書・hooks・labkit・skills を精読、labkit コードの独立監査、2 プロジェクトの devlog / reviews / runs / .lab / git log の全件調査。すべて読み取りのみ。

## 結論

「期待通りに動作しているか」: 機械としては動く。ゲートは発火し、check は違反を出し、flow は done まで進み、レビュー記録 5 本のうち 4 本は実質的な指摘を含む。
「目的に対して最善か」: 否。実運用 2 日分の記録は、統制層が摩擦点のほぼすべてで迂回され、2 箇所では再現性を逆方向に押していることを示す。

- 承認が HEAD に束縛されるため、nla-solver は「承認が通るまで commit しない」運用になり、108 commit 未 push、未コミットのコードで dirty=true の run を実行中。
- 中断 run の status=running を L021 が違反にし、削除は人間専用、人間は 25 時間未応答。結果、commit は SKIP=labkit-check で通している（commit subject に明記）。
- hooks の迂回は 4 形態（包括承認＋スクリプト経由、Python で data/raw を移動、SKIP、scratch へ退避 297 MB）で、すべて devlog に自己申告されている。
- 保存規約の実態: labkit.save ではなく np.savez が 19 箇所。図テンプレートは log 軸すら無く代用で凌いでいる。
- 正本と呼ぶ runs/ と data/external 30 GB に同期・バックアップの手順が無く、移行中に 25 GB の管理外データが消失した。
- 本体の統制コード（flow / state / approvals / reviews / standards）は約 1,700 行で、研究の核（runs / io / viz / rawdata）約 1,600 行を上回る。

## 根本原因（改善の軸）

現行の設計は「Claude に何を打たせないか」（入力側のテキスト照合・禁止・承認）に投資している。目的は「研究記録が検証可能であること」（成果物側）である。
入力側の統制は Windows ではサンドボックスが無効で、公式にも security boundary ではなく、実際に迂回された。しかも迂回のたびに記録が歪む。

**軸: 統制を入力側から成果物側へ移し、検証可能な経路を最も楽な経路にする。**
以下の改善はすべてこの一軸の上にある。互いに矛盾しない。

## 改善点

### A. 承認ゲートと flow（統制の縮小）

1. 承認の束縛先を HEAD から意図（ブランチ名・操作種別・期限）に変える。HEAD 束縛は 2 件の承認を無効化し、commit 抑制と dirty run を生んだ。
2. 保護ブランチ以外への push を無条件に通す。feat ブランチの push は取り返しがつく。最後の砦は GitHub のブランチ保護（AGENT_QUEUE Q-005 のまま未設定）であり、そちらを設定要件にする。
3. 委任を既定にする。v0.4.0 の delegate は導入されたが両プロジェクトで一度も使われていない。plugin cache も 0.3.1 のまま。承認待ちが既定である限り、人間不在時の作業は止まるか迂回される。
4. presence（here/away）を削除する。permission_mode と重複し、監査でも Q-014 で保留のまま。
5. flow の forbid（段階による操作禁止）を削除し、done 条件だけをチェックリストとして残す。forbid は「うっかり防止」と自認しながら、reproduce 段階で禁止された copier update が包括承認下で実行された。禁止は守られず記録だけが矛盾した。
6. migrate flow の freeze 段階に「管理外データのバックアップ先が存在する」を done 条件として入れる。質問で済ませた結果が 25 GB 消失である。
7. improve-standards flow（7 段階の状態機械）を廃し、通常の PR 手順と plugin の版チェックに置き換える。自分のリポジトリを編集する行為に状態機械は過剰で、統制コードの半分がこれに費やされている。

### B. run の来歴（成果物側の強化）

8. meta.json に環境を入れる: uv.lock / Manifest.toml の sha256、主要パッケージ版、OS・CPU・GPU・ドライバ、スレッド環境変数、解決済み data_root / runs_root。現状は同一性（commit・入力 hash）に強く環境に弱い。GPU 情報が無いため nla-solver では CPU 実行と WSL GPU 実行を区別できない。
9. dirty=true のときは git diff を run 内に保存する。未追跡ファイルも dirty に数える（現在は untracked を無視）。dirty run は現状「再現不能と宣告するだけ」で、記録しても使えない。
10. seed を Run の第一級フィールドにする。config に seed が無ければ警告する。
11. 出力に sha256 を付け、figures も outputs に含め、figmeta.json に commit を書く。再描画した図と元の図が区別できない。
12. サイドカーの run_id を meta.json の inputs に引き継ぎ、run 同士の系譜を記録する（io.py の describe_input 呼び出しは MANIFEST も参照せず 2 GB を直書きしており、runs.py と答えが違う）。
13. 異常終了の run を扱える仕組みを入れる: heartbeat または PID を記録し、`labkit runs mark <id> failed --reason` を Claude に許す。L021 は warn にする。削除を人間専用にしたまま違反扱いにするのは、人間の応答時間がそのまま SKIP の時間になる。
14. run ID を UTC＋プロセス ID 込みにする。秒精度＋16 bit 乱数は配列ジョブで衝突する。MANIFEST の書き込みを atomic にする。
15. runs/ と data/ の正本を機械の外に置く手順を labkit に持たせる（`labkit runs push/pull <remote>`、rsync/rclone の薄い wrapper で十分）。「正本は runs/（ただのファイル）」と宣言しながら、その保全手段が無い。MLflow はこの役目を果たさず、両プロジェクトで未使用。

### C. check（体裁ではなく主張を検証する）

16. L033 を「run ID と同じ行」ではなく「結果・観察」節の全数値に適用し、引用付きかを問う。現在は数値を次の行に移すだけで検査を逃れ、逆に「15 / 15」「96 分」のような文脈の数は偽陽性になる。両プロジェクトで「L033 の警告を外すだけの commit」が 4 件ある。
17. 開発ログの必須見出しは存在ではなく本文の有無を検査する。nla-solver 11-02 は 7 見出しがすべて空で、本文は独自見出しに書かれ、check は通っている。見出しは hook 対策の殻になった。
18. `labkit devlog` が 変更ファイル・実行した run・check 結果 を git と runs/ から自動で埋める。人が書くのは 目的・判断・未解決 だけにする。殻を作らせない最も確実な方法は、機械で埋められる欄を機械で埋めることである。
19. L022 を再帰にし、data/interim・processed のサブディレクトリを許す。現状はサブディレクトリ自体が違反になり、nla-solver は 132 MB の派生キャッシュを scratch に逃がした（commit ae4f9b2「interim requires sidecars」）。あわせて「サイドカー不要のキャッシュ層」（data/cache、再生成可能・引用禁止）を正式に設ける。
20. 絶対パス検査を直す: `[A-Za-z]:\\\\` はエスケープ済み文字列しか拾わず、`r"D:\..."` と `D:/...` を見逃す。`/mnt/` を既定に加え、jobs/ を code_dirs に入れる（jobs/ に絶対パスが 40 件以上ある）。
21. np.save / np.savez / torch.save を禁止形式に加える（warn から）。実態は pickle ではなく savez で規約を迂回している。
22. 体裁系の L001 / L004 / L035 / L040 番台は warn に落とすか pre-commit に移し、Stop hook は 主張の検証（L002/3・L022・L032/33）だけで止める。Stop hook が scp 転送中の作業を打ち切らせた記録がある。
23. plugin の版と lab.toml が参照する雛形の版の一致を check する。accelerated-diff-pat は v0.4.0 なのに hooks は 0.3.1 で動いており、devlog が「委任が有効になる」と誤認したまま進んでいる。

### D. 図（禁止ではなく来歴を守る）

24. 描画ライブラリの import 禁止をやめ、プロジェクト内テンプレート（`figspecs/templates/*.py` を labkit fig が登録）を許す。守るべき価値は figmeta.json の来歴であって、matplotlib を書かないことではない。8 種の単軸テンプレートに複数パネル・log 軸の errorbar・帯・棒が無く、論文の図はいずれ外で作られる。add-figure-template skill は「人間に提案して止まる」手順で、不在時には機能しない。

### E. 雛形と文書

25. CLAUDE.md の雛形に「研究契約」の欄（不変条件・検証ゲート・公平性の約束）を設ける。accelerated-diff-pat の CLAUDE.md は 77 % が自前の研究契約で、それが実際に研究を律している。nla-solver は雛形のままで、研究知識は docs/ 直下の 33 ファイルに散在し CLAUDE.md から参照されない。
26. 雛形の pre-commit から data/raw を除外する（end-of-file-fixer が読み取り専用 MANIFEST で落ちて SKIP を生んだ）。`.gitattributes` の `data/raw/** -text` を雛形に入れる（checkout が凍結状態を壊した）。
27. Windows を一級の対象として明記する。サンドボックス無効・hooks はテキスト照合・chmod は属性のみ、を前提にした脅威モデルに書き直す。

### F. 本体の縮減

28. `_labstate.py` のバイト同一コピーをやめ、hooks が labkit を import する形か、1 パッケージに統合する。
29. 未使用・形骸の機能を削る: `lit key` / `lit check`、`human_check`（何も強制しない）、`labkit mode`（正規表現で lab.toml を書き換える）、OPTIMIZATION_LOG.md（676 行の改善サイクル記録を配布物から外す）。
30. Julia 版の位置付けを決める。cli.jl は fig / check / cite を Python に丸投げしており、「同じ API」は wrapper である。両プロジェクトとも use_julia=false。保守するなら対称テストを本気で書き、しないなら削る。
31. テストの穴を埋めるか主張を下げる: mlflow_sync は 0 テスト、L003 / L015 / L021 / L031 / L040〜45、describe_input の manifest / sidecar 分岐、KeyboardInterrupt 経路、LAB_ENV≠local が未テスト。plugin eval 7 ケースは一度も実行されていない。

## 評価できる点（事実として）

- lab-reviewer の記録は実質的で、入力一覧の `[:64]` 切り詰めや「clean HEAD で再実行」という虚偽記述を実際に捕まえている。独立レビューは残すべき部品である。
- `[run:<id>:<key>]` 引用の検証は、適用範囲を直せば本テンプレートで最も価値のある発明である。
- データ原本の sha256 台帳と読み取り専用化は機能し、checkout による破壊も L002/L003 が検出した。
